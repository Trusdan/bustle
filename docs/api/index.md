# Bustle API

Generated by `tools/gen_api_docs.sh` from the `##` doc comments. Do not edit by hand.

- [BustleActionContext](BustleActionContext.md): What a [BustleActionHandler](BustleActionHandler.md) works with for one step: who, the step's parameters, the game time, and two dictionaries it owns.
- [BustleActionHandler](BustleActionHandler.md): The code behind one action id. Subclasses override all three methods. A handler keeps no state of its own: everything about a step lives in `BustleActionContext.data`.
- [BustleActionSequence](BustleActionSequence.md): A short plan as data: steps run in order, with no branching beyond each step's `BustleActionStep.on_fail`. An empty sequence succeeds at once.
- [BustleActionStep](BustleActionStep.md): One step of a [BustleActionSequence](BustleActionSequence.md): an action id, its parameters, and what to do when it fails.
- [BustleAdvertisement](BustleAdvertisement.md): What one option (an object, a place, someone to talk to) offers an agent: how much it relieves each need, what it adds to each need as a side effect, its tags and how far away it is.
- [BustleAffordance](BustleAffordance.md): One placed smart object: a [BustleAffordanceDef](BustleAffordanceDef.md) at a place, perhaps owned. It advertises to agents (`advertise()`) and is used through reservations: `reserve()` → the host walks the agent there and plays the use → `use()`, which applies the def's need effects (leisure scaled by tolerance), takes payment and releases.
**Capacity:** at most `BustleAffordanceDef.capacity` agents hold it at once; a reservation lapses after `BustleAffordanceDef.hold_minutes`. **Ownership:** an owned affordance scores others at `BustleAffordanceDef.others_mult` (0 refuses them), unless `access_hook` says otherwise. **Cost:** each use costs `cost_hook`'s price (the def's price by default; free to the owner), paid to the owner (or `payee`) through a [BustleTradePort](BustleTradePort.md). **Buying:** when the def names an `BustleAffordanceDef.item`, each use buys it from the owner (or payee) with `BustleTradePort.buy()` instead, offered only while `BustleTradePort.can_buy()` says yes, and `cost_hook` and the def's price don't apply. The owner takes one from its own stock with `BustleTradePort.take()`, without paying, offered only while `BustleTradePort.can_take()` says yes, so every stock change goes through the trade port. A payee doesn't buy from itself. Time is whole game minutes, given by the caller.
- [BustleAffordanceDef](BustleAffordanceDef.md): A kind of smart object, as data: what using it does to needs, its tags, how many can use it at once, how long a reservation holds and its price. A bed, a bench and a stall are each one def, placed many times as [BustleAffordance](BustleAffordance.md)s.
- [BustleAffordanceSet](BustleAffordanceSet.md): The placed affordances of a population, by id, so one generic "use something" goal can score them all. `advertisements()` gives the scorer one advertisement per affordance an agent may use (refused, full and unaffordable ones are left out), in id order.
- [BustleAmbitionConfig](BustleAmbitionConfig.md): The ambition library and its numbers, for [BustleAmbitions](BustleAmbitions.md). A starting point, not tuning: a host sets its own, and turns templates off with `BustleAmbitionDef.enabled`.
- [BustleAmbitionDef](BustleAmbitionDef.md): One ambition template, as data: who it suits (personality and circumstances), when it's done, and when it can no longer happen. [BustleAmbitions](BustleAmbitions.md) reads it. Every circumstance, progress input and fact is a name the host fills each update, so a template refers to no particular person, place or system.
- [BustleAmbitionTargets](BustleAmbitionTargets.md): Who the courting and feud ambitions are about, from the society and its social port: fills the inputs [BustleAmbitions](BustleAmbitions.md) reads for `court_someone` and `settle_feud`.
**Courting** (`court_target`): another agent of the society in the same settlement (`settlement_of`), not family (`BustleAmbitionConfig.family_kinds`) and not gone for good (`is_gone`), whose opinion is at least `BustleAmbitionConfig.like_line`; the one it likes most, ties by id. The current target is kept while it still qualifies; while nobody does, there's no target and nothing is boosted. `court_target_gone` is set only when the last target is gone for good and nobody else qualifies; when someone else does, the ambition simply turns to them. 
**Feuds** (`rival`): someone it counts as a rival (the social port's `rival` kind), not gone for good; the current one is kept, else the lowest opinion, ties by id. `rival_cleared` once the current rival no longer has the rival kind (never once they're gone for good, so a feud with someone dead ends moot, not settled), and `rival_gone` once they're gone for good.
- [BustleAmbitions](BustleAmbitions.md): One agent's ambition: a long-term aim, one at a time, from `BustleAmbitionConfig.templates`. Everything follows from the agent's personality and circumstances; nothing here is a chance or a limit shared between agents, and an ambition is never given up.
**Assigning.** An agent with no ambition is given one at the next `update()` (so at spawn, and again after one ends): `pin` when the host set one and it's eligible; otherwise the eligible template with the highest score (`Σ weight × (slider − 50) / 100`), ties going to the lower id. Eligible means enabled, every `BustleAmbitionDef.requires` true, every minimum slider met, not already done, and not completed within `BustleAmbitionConfig.cooldown_days`. A disabled template is never assigned. 
**Completing.** Once the template's progress line or done fact holds (`BustleAmbitionDef.is_done()`), it's completed: `ambition_completed`, the `achieved_ambition` deed (with a `social` port), and its cooldown starts. Its `BustleAmbitionDef.next` is taken when eligible; otherwise the library is scored again. 
**Moot.** Once a `BustleAmbitionDef.moot_facts` fact holds, the ambition can no longer happen: `ended_moot`, with no cooldown, and the library is scored again at once. 
There is no other ending: an ambition stays until it's achieved or moot, however long that takes.
**Bias.** An ambition never acts on its own: `boost()` multiplies the scores of the goals its template names (for `BustleBrain.score_boost`). Boosts never change a band, so nothing here outranks danger, self-care, crime or mental states, orders or duty. They're off while the agent is locked (`locked` in the inputs: an order or quest is followed), while the template is disabled (even when it was assigned earlier), and for `BustleAmbitionConfig.never_boost` goals; the ambition stays assigned all the while.
- [BustleAspirationConfig](BustleAspirationConfig.md): The want and fear library and its numbers, for [BustleAspirations](BustleAspirations.md). Bustle ships no wants or fears: the host supplies both. The numbers are experimental defaults.
- [BustleAspirations](BustleAspirations.md): The aspirations module, for one agent: short-lived wants and event-formed fears. It is separate from ambitions, which keep working the same with it on or off.
**Wants.** Each `update()`, an active want whose `BustleWantDef.is_done()` holds is fulfilled: its satisfaction thought goes to the mood. One that has reached its expiry minute instead expires, with no thought. Then, while fewer than `BustleAspirationConfig.auto_wants` automatic wants are active, the eligible want with the highest score is taken (ties to the lower id). The host may also post wants (`post_want()`); all wants together stay within `BustleAspirationConfig.want_cap`.
A fulfilled want also earns its `BustleWantDef.points`. Points only accumulate: the host spends them (`spend_points()`), for example from `on_points`. Bustle defines no rewards. An active want may boost the goals it names (`boost()`), never past `BustleAspirationConfig.max_want_boost` and never a `never_boost` goal.
**Fears.** An event passed to `update()` forms each fear it triggers, or renews one already formed. While formed, a fear multiplies the scores of the goals and options it avoids (`avoidance()`, for `BustleBrain.score_boost`); it only lowers scores. It ends after its duration, or when its clearing fact is true.
Nothing is random: wants and fears come only from causes and state.
- [BustleAwareness](BustleAwareness.md): One perceiver's awareness list: a [BustleDetectionMeter](BustleDetectionMeter.md) per target it has sensed, keyed by the target's id. Meters are made the first time a target is sensed or heard.
- [BustleAwarenessEntry](BustleAwarenessEntry.md): One line of a perceiver's awareness list: what it knows about one target right now. A snapshot; it doesn't change after it is made.
- [BustleBands](BustleBands.md): The priority bands goals sit in. A band is a whole number and the higher one wins: the scorer chooses only from the highest band that has an eligible candidate, and scores are never compared across bands. The gaps leave room for bands that later features add between these.
- [BustleBrain](BustleBrain.md): One agent's brain, headless: `tick()` takes [BustleSenses](BustleSenses.md) and returns a [BustleIntent](BustleIntent.md). It never reads the scene and never runs by itself; whoever drives it decides how often to tick.
- [BustleCandidate](BustleCandidate.md): One scored choice: a goal, and the option it would use (empty for a goal without advertisements). It keeps the raw score, the score used for selecting, whether it is eligible, and the reasons behind the numbers.
- [BustleCareerDef](BustleCareerDef.md): A career track, as data: the ranks of one standing job. A career is the job itself, held as a role with a routine ([BustleRoleSchedules](BustleRoleSchedules.md)); the track adds ranks, a wage per rank and a skill minimum per rank. Its career block is the routine's block for `activity`: the agent works it off site when `off_site` is set. Bustle ships none; the host supplies every track.
- [BustleCareerRank](BustleCareerRank.md): One rank of a career track, as data: its id, the wage a career block earns at it, the skill level an agent needs to hold it, and how it is reviewed. [BustleCareerDef](BustleCareerDef.md) lists them lowest first. The review numbers are experimental defaults.
- [BustleCareers](BustleCareers.md): The careers module: ranks on standing jobs. A career is not a second job: it is the agent's standing job (a role with a routine, see [BustleScheduleRoster](BustleScheduleRoster.md)) held at a rank of a [BustleCareerDef](BustleCareerDef.md). The rank sets what the track's career block pays, through the agent's schedule (`BustleSchedule.wages`), so it is paid at the block's end like any shift and only if attended. While an agent attends an off-site career block it is away (`is_away()`), and the host takes it out of the world until the block ends.
`update()` closes whole days into a performance score (`day_performance()`: mood, skill and attendance) and reviews the agent after each window of `BustleCareerRank.review_days` days. A window at or above the rank's `BustleCareerRank.promote_if` makes a promotion due; at or below `BustleCareerRank.demote_if`, a demotion. `review_hook` grants or refuses it; with none, it is granted. Reviews can leave the agent a thought, when it has a mood.
Agents with no career keep their job, routine and wages exactly as before. An agent whose job is no longer the track's role leaves the track. Nothing is random: the same mood, skill and attendance give the same reviews.
- [BustleChoiceKeeper](BustleChoiceKeeper.md): Hysteresis around [BustleUtilityScorer](BustleUtilityScorer.md): it remembers an agent's current choice so the agent doesn't flicker between near-equal goals, and keeps failed goals out for a while.
- [BustleClockPort](BustleClockPort.md): The game clock, in whole game minutes. A host extends this and overrides `now_minutes()` and `day_key()` to read its own clock. The standalone default keeps its own minute count, starting at 0 and moved on with `advance()`; a day is `MINUTES_PER_DAY` minutes, so minute 1439 is in day 0 and minute 1440 starts day 1.
- [BustleCombatPort](BustleCombatPort.md): Fighting, handed to the host. A host extends this to drive its own combat, and reports progress through `status()` and the result through `outcome()`. The standalone default resolves at once and harmlessly: engaging leaves the fighter RESOLVED, with no damage, no winner and nobody killed.
Every fight has an intent: `subdue` (the default) or `kill`. A host's combat should pass a subdue fight's immediate damage through `BustleConflict.filter_damage()`. A target may still die, then or later of its wounds; the host's health system decides, and reports it in `outcome()`.
- [BustleComfort](BustleComfort.md): The comfort hook: an agent who notices a friend in a low mood is offered comforting them. For each such friend it adds an advertisement to the agent's [BustleSenses](BustleSenses.md) (option id: the friend; relief: `need`, larger the lower the friend's mood; tags: `tags`) and sets the `need.<need>` input to 1, so a goal with `BustleGoalDef.uses_advertisements` can pick whom to comfort and a `converse` step with a comfort opener can do it.
How much an agent cares is its need weight, `need.<need>.weight` in its [BustleModifierSet](BustleModifierSet.md), which the brain reads for every advertised need: a trait raises or lowers it with `BustleTraitDef.mults`. Nothing here depends on the mood module: a mood is anything with a `mood` number.
- [BustleCompatibility](BustleCompatibility.md): How well two agents get on by nature, from -1 (they grate) to 1 (they click). It is fixed for a pair in a world: the same for the same two ids and world seed, the same both ways round, and different in another world. It comes from a 64-bit FNV-1a hash of the seed and the two ids in sorted order. A host may blend in how close the two agents' personality sliders are.
- [BustleConflict](BustleConflict.md): Fight, flee or fetch help, in the CRITICAL band. Nothing here is left to chance: every fight starts from a cause, and every intent to kill has a reason.
**Causes.** An agent that `notice()`s someone it regards as hostile (by the disposition port, never by opinion) is in a conflict. A `quarrel()` the host starts comes to blows only when its provocation and the agent's grudge reach a threshold set by temper and mood. A fetched ally fights for whoever fetched it.
**Stances.** Bold or hot-tempered agents fight; timid ones fetch a nearby ally, or flee. `fill_inputs()` writes the stance as the scorer's `threat.fight`, `threat.flee` and `threat.fetch_help` inputs, which the goals from `goal_defs()` read, and the `fight`, `flee` and `fetch_help` actions carry them out. When a conflict ends, its inputs go and the agent's usual goals (its schedule) win again.
**Intent.** A fighter means to `SUBDUE` unless it has a reason to `KILL`: `defend_life` (its threat means to kill it, and it is cornered or its life is threatened; checked again every fight tick, so a fight can escalate), or a reason the host gives through `lethal_reason_of`. `intent_changed` reports every change with its reason.
**Events.** Every fight that ends emits `assaulted`, and one in which the target died also `killed`, whatever the intent: a subdue fight can still kill. Each carries `{act, cause, cause_detail, intent, intent_reason, killed, at}`. `act` is a fixed id for the fight (attacker, victim and the minute it started); a host stores it on the wounds it causes, so a victim who dies later of them can be traced to the fight.
- [BustleConflictConfig](BustleConflictConfig.md): The numbers behind [BustleConflict](BustleConflict.md): who fights, how far help is looked for, how far agents flee, and how much it takes for a quarrel to come to blows. Nothing here is a chance: every fight and every intent to kill has a reason.
- [BustleConsideration](BustleConsideration.md): One factor in a goal's score: a `Curve` sampled at one input (see [BustleInputs](BustleInputs.md)). The curve's output is used as it is, signed and unclamped: a curve's tangents can overshoot its value range.
- [BustleConversation](BustleConversation.md): A conversation: a few turns between two agents, each turn one interaction picked by weight and recorded through `BustleSocialInteractions.interact()`. The two sides take turns to speak, the initiator first.
It runs two ways with the same results. `run()` does a whole conversation at once (for agents nobody is watching); [BustleConverseAction](BustleConverseAction.md) does one turn per tick (for agents in view). Both go through `begin()` and `step()`, which keep everything in a plain-data state, and every choice is seeded by the world seed, the pair, the start minute and the turn, never by when a tick happens.
An interaction's weight is its `BustleInteractionDef.weight`, bent by: 
- the speaker's sliders (`BustleInteractionDef.slider_weights`); 
- the speaker's modifiers: `conversation.<id>.weight`, which traits set; 
- the speaker's opinion of the listener: a high one makes positive interactions likelier and negative ones rarer (`opinion_weight`); 
- the speaker's mood: below 50, `curt` interactions grow likelier (`curt_mood_scale`). 
A low mood also lowers the chance of starting at all (`start_mood_scale`), and a recipient can turn a start away (`accepts`).
- [BustleConverseAction](BustleConverseAction.md): `converse`: a [BustleConversation](BustleConversation.md) one turn per tick, for agents in view. The partner is `params.with`, or the step's option id when that's empty (as when a goal picks someone to talk to from advertisements, like the comfort hook's). `params.opener` names the first turn's interaction. A turn happens on the first tick at or after its minute, so the results match `BustleConversation.run()` for the same start.
It fails with `no_partner`, `turned_away` (the partner won't talk now, `BustleConversation.accepts`), `declined` (the roll to start failed) or `nothing_to_say`. While it runs, the output names the partner as `talk_to`, and each turn's result is in it as `turn`. The conversation's state is plain data in the step's data, so it saves with the runner.
- [BustleCrime](BustleCrime.md): Desperate theft, in the `BustleBands.GUARDED` band. Nothing here is left to chance: an agent steals when its circumstances and its personality add up, every time they do, and never otherwise. There is no limit on how much crime a place sees; how often it happens follows from who lives there and how hard pressed they are.
`consider()` runs the guards, in order. Each must pass: 
1. crime is allowed: the developer setting `BustleCrimeConfig.SETTING` and `enabled` (neither is a game option); 
2. the agent is a known agent, not in `exempt` and not held by `is_locked`; 
3. need: one of `BustleCrimeConfig.needs` presses at least `BustleCrimeConfig.min_need`, and the agent owns nothing that eases it (an agent that already has what it needs, stolen or not, isn't driven to take more); 
4. personality: that pressure plus `Σ weight × (slider − 50) / 100` over `BustleCrimeConfig.slider_weights` reaches `BustleCrimeConfig.threshold` (honesty holds an agent back; greed and boldness push it on); 
5. opportunity: an item in the agent's area, owned by someone else, not protected, that eases the need, where nobody else would see (`is_observed`). 
When they all pass, the agent's `fact.steal` input is 1 (`fill_inputs()`), so the `steal` goal from `goal_defs()` can run its `steal` action, which moves the item through the property port and emits `theft`. A theft only moves an existing item, and never makes anyone mean to kill: what follows is for the host.
A theft by someone who isn't an agent of the society (the player's character, for example) goes through `record_theft()` instead: it emits the same `theft` and moves nothing.
- [BustleCrimeConfig](BustleCrimeConfig.md): The numbers behind [BustleCrime](BustleCrime.md). Nothing here is a chance: a theft happens when its circumstances and the agent's personality add up, every time they do.
- [BustleCrimeWatch](BustleCrimeWatch.md): What becomes of each theft: who perceived it, who it's reported to, and the deed it leaves when nobody did. Every `BustleCrime.theft` becomes a record, and every record is either witnessed or a deed (an open trace that its owner finds later, and that the stolen goods themselves point to). Each witness, and an owner who finds a deed, remembers it and then decides what to do about it: one of `BustleWitnessJudge.OUTCOMES` (`should_report`).
There are no made-up witnesses: an agent witnesses a theft only when `perceives` says it perceived it. By default that's every other agent in the place who isn't incapacitated (the health port). The thief's own judgement (`BustleCrime.is_observed`) can be wrong when the host gives it one, for example an onlooker the thief didn't notice, so a theft can have witnesses. With both defaults, a thief only steals where nobody can perceive it, so every theft is a deed.
Reports go to a role (`authority_role`), never to a named agent: the host decides who holds it (the roles port) and what follows. Reporting, telling the victim and gossiping are errands: the word counts only when the agent reaches whoever it's for, face to face (`deliver()`, run by the `deliver` goal in the guarded band). Until then the errand can wait (nobody holds the role), pause (`can_travel`), be forgotten (its memory fades) or be dropped under `intimidate()`. Whoever hears it second-hand learns of the theft and decides in turn. `instant` delivers at once instead, for developers and tests only. A confrontation is words, never a fight or an intent to harm. Nothing here punishes, fines or harms anyone.
- [BustleDebug](BustleDebug.md): Whether Bustle's debug tools may run. They run only in debug builds (the editor and debug exports); in a release export the console and overlay do nothing. Hosts can also leave `addons/bustle/debug/` out of release exports with an export filter.
- [BustleDebugConsole](BustleDebugConsole.md): Text commands for inspecting and steering a [BustleSociety](BustleSociety.md) while developing. `run()` takes one line and returns the answer as text. It does nothing in release builds (see [BustleDebug](BustleDebug.md)).
- [BustleDebugOverlay](BustleDebugOverlay.md): A world overlay for developing: a label above each agent's attached body with its ring, band, goal, step, top 3 scores and need inputs (from [BustleInspector](BustleInspector.md)). Toggle `enabled` at runtime. Off, it stops processing and frees its labels, so it costs nothing. It can't be enabled in a release build (see [BustleDebug](BustleDebug.md)).
- [BustleDeliverAction](BustleDeliverAction.md): `deliver`: goes on with the agent's oldest errand through `BustleCrimeWatch.deliver()`. While it still has to get there, it asks the host to move the agent towards the target (`move_to`, `talk_to` and `gear` in the output, the gear being `BustleCrimeWatch.travel_gear`); Bustle names where, the host moves the body. Done once the word is delivered, forgotten, or there's nobody to reach yet.
- [BustleDetectionMeter](BustleDetectionMeter.md): One observer's awareness of one target: a meter from 0 to 1 that sight and hearing fill and that decays when neither reaches the target, and four states driven by it.
- [BustleDirectorPort](BustleDirectorPort.md): A storyteller that paces events. A host or the director module extends this. The standalone default allows every event (any limit on drama is left to the core's own budget).
- [BustleDispositionPort](BustleDispositionPort.md): How one actor regards another: hostile, neutral or friendly. A host plugs in its own source (factions, reputation) by extending this class and overriding `disposition()`. The standalone default reads a [BustleDispositionTable](BustleDispositionTable.md) if one is given, and is neutral otherwise.
- [BustleDispositionTable](BustleDispositionTable.md): A data table of dispositions between groups, and optionally between two actors. Change a `.tres` value and two actors become hostile, neutral or friendly with no code change. [BustleDispositionPort](BustleDispositionPort.md) reads it.
- [BustleEnvironmentPort](BustleEnvironmentPort.md): Rooms and surroundings. The host computes its rooms and their scores; Bustle never detects rooms or looks at what is in them. A host either extends this (overriding `room_of()` and `scores()`) or fills the built-in store with `set_room()` and `set_scores()`. The standalone default has no rooms and no scores. An agent in a room is indoors and one in no room outdoors (`conditions()`), for needs that rise or fall with that.
- [BustleFearDef](BustleFearDef.md): One fear, as data: the event that forms it, what it makes the agent avoid and for how long. [BustleAspirations](BustleAspirations.md) reads it. Bustle ships none; events, goals and inputs are the host's names.
- [BustleFetchHelpAction](BustleFetchHelpAction.md): `fetch_help`: goes to the ally `BustleConflict.notice()` picked (`move_to` and `talk_to` in the output) and, once within `REACH` metres (or at once without positions), hands the threat to it with `BustleConflict.call_help()`. When there's no ally or the ally can't come (it has a conflict of its own), it switches to fleeing (`BustleConflict.switch_to_flee()`) and the `flee` goal takes over. Done either way.
- [BustleFightAction](BustleFightAction.md): `fight`: engages the agent's threat through the combat port with its intent, and names it as the output's `attack_target`. Every tick it works the intent out again (`BustleConflict.update_intent()`) and engages again when it changed, so a fight can escalate. Done when the port reports the fight RESOLVED (then `BustleConflict.finish()` reports it) or the conflict was cleared. Fails with `no_threat` when the agent has none.
- [BustleFindPerson](BustleFindPerson.md): Works out where to look for someone, in order: sense them now (`sense`); remember where they were ([BustleMemory](BustleMemory.md)); guess from their routine (`routine`); ask the people the seeker can ask (`ask_whom`), whose memories answer; or give up. Giving up starts a cooldown for that seeker and target, during which `find()` fails at once, so an agent doesn't search for someone nobody knows about every tick. What is learnt by asking or guessing is noted in the seeker's memory (`BustleMemory.TOLD`, `BustleMemory.ROUTINE`).
The host supplies each source as a `Callable`; empty ones are skipped. Cooldowns live only in memory: an ended one is dropped when that search runs again, and none are saved.
- [BustleFleeAction](BustleFleeAction.md): `flee`: runs straight away from the agent's threat (`move_to` in the output, aimed `BustleConflictConfig.flee_margin` past the safe distance so a body that stops a little short still gets there) until it is `BustleConflictConfig.flee_distance` away, then clears the conflict. Without positions it gets away at once. Done when the conflict is over.
- [BustleGoalDef](BustleGoalDef.md): A goal an agent can choose: its band, base weight, preconditions and considerations. Its score is `base_weight × Π consideration`. A goal that uses advertisements makes one candidate per known option, scored as its own score × the option's advertisement score.
- [BustleGoalLibrary](BustleGoalLibrary.md): The goals an agent chooses from.
- [BustleHealthPort](BustleHealthPort.md): Health, owned by the host (damage, illness, medicine). A host or the health module extends this. The standalone default says everyone is healthy.
- [BustleHoldAction](BustleHoldAction.md): `hold`: stays put and never finishes (`held` in the output), so an order that ends with it holds until it's cancelled, as a lock's order does.
- [BustleIdleAction](BustleIdleAction.md): `idle`: idles in `params.style` (put in the output as `animation`) for `params.minutes` game minutes, default 0 (one tick). A negative or non-finite number of minutes fails the step (`bad_params`).
- [BustleImportReport](BustleImportReport.md): What happened when a saved society was imported. When `ok` is false nothing was changed: an import is all or nothing.
- [BustleInfo](BustleInfo.md): Facts about the installed Bustle addon.
- [BustleInputs](BustleInputs.md): The fixed vocabulary of scorer inputs. An input key is a family and a name, such as `need.food` or `trait.sociability`; the families are fixed here, and the names within them are data. Adding a family is a reviewed code change; using one is data. Input values reach the scorer already normalised by whoever supplies them.
- [BustleInspector](BustleInspector.md): Reads an agent's state for debugging, from what the brain already holds: the scorer's own candidates from the last tick (never recomputed), the last intent, the runner and the order queue. Parts that come from modules not installed yet are marked `{available: false, module: <name>}` instead of being made up. Read-only.
- [BustleIntent](BustleIntent.md): What a [BustleBrain](BustleBrain.md) wants its agent to do after one tick. A body (in the host) applies it. The goal fields say what was chosen and why; the action fields come from the running step's `BustleActionContext.output`, copied only when they have the right type.
- [BustleInteractionDef](BustleInteractionDef.md): One kind of interaction between two agents, as data (a greeting, a chat, kind words, a slight, an insult): how much it moves each side's opinion of the other, for how long, how much the pair's compatibility and each side's mood bend that, and the thoughts it leaves. See `BustleSocialInteractions.outcome()`.
- [BustleJobBoard](BustleJobBoard.md): A board of posted, one-off work that agents claim. An employer posts a [BustleWorkType](BustleWorkType.md); an agent that passes its gates (role, skill level, tags) can claim it; the claim is exclusive and lasts until the work is completed, released, cancelled or expired. Standing jobs stay roles and schedules: the board doesn't touch them.
An agent takes the open posting it wants most (`BustleWorkType.score()`) among those it can do, ties going to the earlier posting id. When several agents want one posting at the same time, `assign()` gives it to the highest score, ties going to the lower agent id. Nothing is random: the same postings, agents and clock give the same claims. Install it as `society.ports.work.board`.
**With a brain.** `advertise()` offers an agent's postings to its brain as options, so a job goal weighs them against its other goals. The board only ranks: it never leaves out work an agent dislikes, it just makes that work less appealing. When a brain picks a posting, the host calls `request()`; `settle()`, at the end of the tick, gives each requested posting to the highest score, ties going to the lower agent id. `work()` then adds the work done, with practice through the skill port, and completes the posting once its type's minutes are done, paying the wage through the trade port.
- [BustleJobPosting](BustleJobPosting.md): One posting on a [BustleJobBoard](BustleJobBoard.md): a work type someone wants done, open until an agent claims it, and gone once it's completed, cancelled or expired. Read it; change it only through the board.
- [BustleJobSeeker](BustleJobSeeker.md): One agent looking at the job board: its id and what the board's scores and gates read about it. The host fills it when the agent looks for work. Roles and skill levels come from the ports, not from here.
- [BustleLeisure](BustleLeisure.md): Leisure with kinds and tolerance, so agents vary what they do for fun. Each kind (for example a walk, music, games) has a tolerance from 0 to 1. Every use of a kind adds `tolerance_per_use` to it, and tolerances fall by `tolerance_decay_per_day` per game day. `adjust()` scales an option's relief of `need` by `1 − tolerance`, and to 0 at or past `boredom_threshold`, so the scorer stops picking a kind it is bored of and turns to another. An option's kind is its first tag that is one of `kinds`.
The defaults are a starting point, not tuning: a host sets its own. Tuning that isn't a finite number counts as 0 (the threshold as 1), and tolerances stay within 0 to 1.
- [BustleLifeStagePort](BustleLifeStagePort.md): Life stages (child, adult and so on, as the host defines them). A host or the life-stages module extends this. The standalone default is ageless.
- [BustleLightProbe](BustleLightProbe.md): Answers how much light reaches a point. Abstract: a project extends it (or uses [BustlePointLightProbe](BustlePointLightProbe.md)) and overrides `sample()`. The base is always dark.
- [BustleLightSample](BustleLightSample.md): How much light reaches one point, from a [BustleLightProbe](BustleLightProbe.md).
- [BustleLightSource](BustleLightSource.md): One point light, as [BustlePointLightProbe](BustlePointLightProbe.md) sees it. Plain data; the project keeps it in step with whatever torch, candle or window it stands for.
- [BustleLock](BustleLock.md): A host's pin on one agent: a place to stay at, a goal (or sequence) to run, or both, under a `lock_id`. `BustleSociety.lock()` holds it; while any lock is held the agent is locked (`BustleSociety.is_locked()`). A lock is just a lock: what it's for is the host's.
- [BustleMemory](BustleMemory.md): One agent's memory of where people, places and items are. Each entry is one subject of one kind (`PERSON`, `PLACE`, `ITEM`) with an area, maybe a position, its source (`SAW`, `HEARD`, `TOLD`, `ROUTINE`) and a strength that halves every half-life of its kind ([BustleMemoryConfig](BustleMemoryConfig.md)). An entry is forgotten when its strength falls below the config's threshold, and past capacity the weakest entry goes.
A new note about a subject replaces the old one when it is at least as strong as what is left of the old one, so a fresh sighting beats an old rumour but a rumour doesn't overwrite a fresh sighting. Time is whole game minutes.
- [BustleMemoryConfig](BustleMemoryConfig.md): How a [BustleMemory](BustleMemory.md) holds and forgets, as data. Each kind of memory fades on its own half-life in game hours; each source starts at its own strength. An entry is forgotten once its strength falls below `forget_below`. These are starting numbers, not tuning: a host sets its own.
- [BustleMemoryFeed](BustleMemoryFeed.md): Writes what agents perceive into their memories, driven by events: each time a perceiver becomes alert to a target (`BustlePerceptionWorld.perception_changed`), the perceiver's [BustleMemory](BustleMemory.md) notes where the target is (`BustleMemory.SAW`), and when it loses track (back to unaware) it notes where the target was last known. Nothing polls.
Both halves of a loss-of-track note come from what the perceiver actually observed: the position is the world's last-known one, and the area is the one the target was in when this perceiver last became alert to it, never where the target is now. With no such observation, or no last-known position, nothing is written. The note is stamped with the minute track was lost. Suspicion alone writes nothing.
- [BustleMentalAction](BustleMentalAction.md): `mental`: acts out the agent's mental state through [BustleMentalBehaviour](BustleMentalBehaviour.md). It names where to go (`move_to`) and the host moves the body: 
- withdraw: home, and stays there (`withdrawn` in the output: a host's own visits should be turned away while it's set; see `BustleMentalBehaviour.accepts()`); 
- wander: walks from place to place; 
- binge: uses its indulgence (`use_affordance`); 
- lash out: goes to its target (`talk_to`) and, once there, insults it (`insulted`), then is done. 
It runs while the state lasts; the goal stops being eligible when the state ends.
- [BustleMentalBehaviour](BustleMentalBehaviour.md): What agents do in a mental state, for a whole society: the circumstances each [BustleMentalState](BustleMentalState.md) decides from, the state's modifiers, the goals that act it out (in `BustleBands.GUARDED`, so urgent self-care outranks them and orders and duty don't), and lashing out.
**Modifiers.** While an agent is in a state, `BustleMentalConfig.state_modifiers` for it are set on the agent's [BustleModifierSet](BustleModifierSet.md) (its mood's), and removed when it ends. 
**Goals** (`goal_defs()`, each running the `mental` action, [BustleMentalAction](BustleMentalAction.md)): withdraw goes home and turns others away (`accepts()`), wander walks about, binge uses the indulgence it knows of, and lash out goes to its target and insults it. Sulk, high spirits and inspiration are modifiers only. 
**Locks.** While `is_locked` holds, no state starts, the goals aren't eligible and the modifiers are off; when it ends, the state is evaluated again. 
**Lashing out** is words only. The target is the most disliked person nearby: in the same area and within `BustleMentalConfig.lash_radius`, disliked (opinion below the dislike line) or a rival; rivals first, then the lowest opinion, ties by id. Each person can be insulted at most `BustleMentalConfig.insults_per_victim` times an episode. The insult is emitted as `insulted`; with a `conflict`, the insulted agent then quarrels through the usual fight rules, which never mean to kill. Nothing here sets any intent.
- [BustleMentalConfig](BustleMentalConfig.md): The numbers behind [BustleMentalState](BustleMentalState.md). A starting point, not tuning: a host sets its own. The modifiers `mental.break_threshold` (added to `break_threshold`, so traits can move it) and `mental.inspired` (above 0: a trait that opts in to inspiration) adjust them per agent.
- [BustleMentalState](BustleMentalState.md): One agent's mental state: which of `BustleMentalConfig.states` it's in, if any, and when that starts and ends. Everything follows from its mood, personality and circumstances; nothing here is a chance, a timer between episodes or a limit shared between agents.
**Starting.** Each `update()`, an agent in no state may start one: 
- a low state when mood is below its break threshold (`BustleMentalConfig.break_threshold` plus the `mental.break_threshold` modifier). The highest score wins, ties going to the earlier state (quieter first). A state that needs an indulgence or a target is skipped without one. Lashing out needs a target the agent dislikes (opinion below `BustleMentalConfig.dislike_line`) or that the host marks as a rival; a liked target doesn't count. The dislike pushes it further. 
- inspiration when mood is above `BustleMentalConfig.inspired_above` and diligence or curiosity is above `BustleMentalConfig.inspired_slider` (or a trait opts in through the `mental.inspired` modifier); else high spirits when mood is above `BustleMentalConfig.high_spirits_above`. Inspiration beats high spirits: an agent in high spirits whose mood rises far enough becomes inspired. 
Nothing starts while the circumstances say the agent is locked, or while mental states are off (`enabled`, `BustleMentalConfig.allowed()`).
**Ending.** A state ends when its duration is up, or sooner when mood recovers (a low state once mood rises to the threshold plus `BustleMentalConfig.recover_margin`; a high one once mood drops below its exit line). When a low state ends, the agent gets the catharsis thought, an aftermath only: it can start another state as soon as its mood is below the line again. This part only decides and records states; what an agent does in one comes later.
- [BustleMentalStateDef](BustleMentalStateDef.md): One mental state, as data: what it does (`behaviour`), whether it's a low or a high state, how personality weighs it, what circumstance it needs and how long it lasts. What a state can do is fixed by `Behaviour`; there is no field for harming anyone, the agent included, or for any intent.
- [BustleModifierSet](BustleModifierSet.md): Numbers that sources (a trait, a mood, an injury) add to or multiply, by key, so modules read one value without knowing where its parts came from. A key is dot-separated lower-case names, such as `need.company.rate` or `tag.social.mult`.
- [BustleMood](BustleMood.md): One agent's mood and thoughts. Mood heads for its target, which is the baseline plus every active thought's value (each repeat of a thought counting `BustleThoughtDef.stack_mult` of the one before, times the `thought.tag.<tag>` modifiers), clamped to the config's range. It moves at the config's rise or fall rate per game hour, times the agent's volatility, and stands still while the agent sleeps.
`advance_to()` is closed-form: it splits the time only where a thought expires, so an OFF_SCREEN agent's day costs one step per expiry. Every thought keeps its reason (`reasons()`). The dominant emotion is the emotion with the largest total of absolute thought values; on a tie the current one stays.
- [BustleMoodConfig](BustleMoodConfig.md): How mood moves, as data. Mood runs from `min_mood` to `max_mood`; it heads for its target (the baseline plus every active thought) at `rise_per_hour` when below it and `fall_per_hour` when above, both times `volatility`. These are starting numbers, not tuning: a host sets its own. Per agent, the modifiers `mood.baseline`, `mood.volatility`, `mood.rise.mult` and `mood.fall.mult` adjust them.
- [BustleNeedDef](BustleNeedDef.md): One need, as data: how fast its pressure rises (0 = fine, 1 = urgent), under which conditions, how it changes while other conditions hold, and its response curve. Bustle ships no needs of its own; a host defines them. Every rate defaults to 0.
Each game hour the pressure changes by `rate_per_hour` × the agent's `need.<id>.rate` modifier (only while one of `rises_when` holds, or always when that is empty), plus `condition_rates` for every condition that holds. The rate modifier scales the rises only, never a fall (a negative base rate or condition rate).
- [BustleNeedSet](BustleNeedSet.md): One agent's needs: each [BustleNeedDef](BustleNeedDef.md) and its current pressure, from 0 (fine) to 1 (urgent). `advance()` moves every pressure on by game minutes under the conditions that hold (the host names them: `awake`, `asleep`, `alone` and so on). Changes are linear and clamped, so one long step equals many short ones under the same conditions, which is what OFF_SCREEN agents need. Using an option lowers (`relieve()`) or raises (`raise()`) a pressure. `fill_inputs()` gives the scorer its `need.<id>` inputs.
**The social pair.** Two needs cover loners and extroverts with the same rules: one that rises while `alone` (company) and one that rises while `crowded` (too many people). `social_conditions()` names which holds from how many people are near and the agent's crowd tolerance (the `social.crowd_tolerance` modifier, base `DEFAULT_CROWD_TOLERANCE`).
- [BustleNoiseEvent](BustleNoiseEvent.md): A one-off sound (a thrown object landing, a lock breaking) that the project broadcasts to observers. Anyone within `radius` of `position` can hear it.
- [BustleNoiseModel](BustleNoiseModel.md): How far a target's noise carries, in metres: the project's movement radius × a surface factor × a gear factor, times the stealth-skill multiplier. It keeps no state; the numbers come from [BustleStealthRules](BustleStealthRules.md).
- [BustleNpcState](BustleNpcState.md): One agent's state, independent of any scene: who it is, where it is, its brain and its modules' data. A body (a scene node the host makes) can be attached and freed at any time; the state stays in the [BustleSociety](BustleSociety.md).
- [BustleOrder](BustleOrder.md): A task given to an agent from outside (a player or a quest): a sequence to run, optionally on a target. Ordinary orders sit in `BustleBands.ORDERED`, below urgent self-care; a `forced` one sits above everything, danger included.
- [BustleOrderQueue](BustleOrderQueue.md): One agent's orders, first in, first out, with the runner for the front one. A [BustleBrain](BustleBrain.md) owns it and decides each tick whether the front order runs.
- [BustlePassionDef](BustlePassionDef.md): A passion for one skill, as data: how much faster an agent with it learns, which personality sliders make an agent take it up when it has no passion assigned, and an optional thought held while it does that skill's work. [BustleSkills](BustleSkills.md) reads it. The numbers are experimental defaults.
- [BustlePerceivable](BustlePerceivable.md): Lets its actor be sensed. Place it where others look and listen (about chest height). Its owner keeps `visibility`, `noise_radius` and `carries_light` current (for example from [BustleVisibilityModel](BustleVisibilityModel.md) and [BustleNoiseModel](BustleNoiseModel.md)); the defaults are a visible, silent actor with no light.
- [BustlePerceiver](BustlePerceiver.md): Gives its actor senses. Place it at the actor's eyes, facing the way it looks (its -Z). It registers with the [BustlePerceptionSystem](BustlePerceptionSystem.md) under `actor_id`; pair it with a [BustlePerceivable](BustlePerceivable.md) with the same id if the actor can also be sensed. Differences between actors come from the `profile` data, never from code.
- [BustlePerceptionActor](BustlePerceptionActor.md): One actor in a [BustlePerceptionWorld](BustlePerceptionWorld.md): what others can sense of it and, if it has a `profile`, how it senses them. The host (or a perception component) keeps the fields up to date; the world reads them when it ticks. Any actor can perceive any actor.
- [BustlePerceptionProfile](BustlePerceptionProfile.md): How one kind of observer notices a target: what it senses, how fast its [BustleDetectionMeter](BustleDetectionMeter.md) fills and empties, and when it changes state. A project supplies one `.tres` per kind of observer; the defaults here are PROPOSED tuning, not final values.
- [BustlePerceptionSystem](BustlePerceptionSystem.md): Runs a [BustlePerceptionWorld](BustlePerceptionWorld.md) for a scene: [BustlePerceiver](BustlePerceiver.md) and [BustlePerceivable](BustlePerceivable.md) nodes register with it, it copies their state into the world each physics frame, ticks the world and casts the sight rays with physics.
- [BustlePerceptionWorld](BustlePerceptionWorld.md): Every actor's senses in one place, with the same rules for whoever looks and whoever is looked at. Headless: the host adds [BustlePerceptionActor](BustlePerceptionActor.md)s, keeps their fields current, supplies a sight-ray check (`line_of_sight`) and calls `tick()`.
- [BustlePersonality](BustlePersonality.md): One agent's personality: 8 sliders every agent has, from 0 to 100 (50 is average), and up to `MAX_TRAITS` traits on top. Sliders reach the scorer as the inputs `trait.<slider>`, from 0 to 1. Traits are data ([BustleTraitDef](BustleTraitDef.md)); `apply()` puts them into effect: their modifiers into a [BustleModifierSet](BustleModifierSet.md) (one source per trait), their needs into a [BustleNeedSet](BustleNeedSet.md), their goals into a [BustleGoalLibrary](BustleGoalLibrary.md) and their permanent thoughts into a mood (anything with `set_held(def, held, details)` and `count(id)`). Applying again after a change adds what is new and takes away what a removed trait brought, and nothing else: a need, goal or thought the agent already had before a trait wanted it is never added again, never owned by the personality and never removed by it.
- [BustlePointLightProbe](BustlePointLightProbe.md): An ambient level plus point sources. Each enabled source adds `energy × (1 − distance / range)²` inside its range; the total is clamped to 1. An optional `occluded` check lets a project drop a source that something blocks.
- [BustlePorts](BustlePorts.md): One of each port, starting with every standalone default, so Bustle runs with no host. A host replaces the ones it implements by assigning its own subclass.
- [BustlePropertyPort](BustlePropertyPort.md): Who owns which things, and where they are. A host extends this to use its own items. The standalone default keeps an in-memory register.
An item is a plain record: `{id, owner_id, place, relieves, protected}`, where `relieves` is need → amount (what having it would ease) and `protected` marks something that can never be taken (a host marks its own: keepsakes, things a story needs). `transfer()` only ever moves an existing item from its owner to someone else. Only the host makes items (`register()`) or uses them up (`remove()`); theft never does.
- [BustleRelationshipRules](BustleRelationshipRules.md): When repeated deeds make one agent count another a friend or a rival, as data. A kind forms when the opinion reaches its level and enough deeds of the right sign (opinion entries with a deed in their reason) fall inside the window; it lapses only once the opinion crosses back past its release level, so it doesn't flicker. These are starting numbers, not tuning.
- [BustleRoleSchedules](BustleRoleSchedules.md): Jobs as roles, as data: the routine that comes with each role, and who pays its wages. An agent holding one of these roles (through the roles port) has that role as its job and follows its routine. See [BustleScheduleRoster](BustleScheduleRoster.md).
- [BustleRoleTable](BustleRoleTable.md): Who holds each role at the start, for the default [BustleRolesPort](BustleRolesPort.md).
- [BustleRolesPort](BustleRolesPort.md): Who holds which role (a job or an office). A host extends this and overrides `holder_of()` and `roles_of()`, and emits `holder_changed` when a holder changes. The standalone default is a static table, read from a [BustleRoleTable](BustleRoleTable.md) if one is given, changed with `set_holder()`. What a role means is the host's business.
- [BustleRomance](BustleRomance.md): The romance module: the courtship ladder of none, courting, partner, engaged and married. Every status is a relationship kind written both ways through the social port (`BustleSocialPort.set_kind()`), so the built-in store and a bridge to a social engine both carry it.
`update()` moves a pair along the ladder from causes and state alone. Courting starts when both opinions and their compatibility reach the [BustleRomanceRules](BustleRomanceRules.md) lines; it becomes a partnership after the courting days if both opinions reach the partner line. Engaged and married come only from `request()` with the host's `confirm_hook` approving. A pair breaks up when either opinion falls below its release line, or when the host calls `end()`; both then get the breakup thought. An agent with a partner or more never starts courting anyone else, and courting is one at a time. Nothing is random.
- [BustleRomanceRules](BustleRomanceRules.md): The lines of the courtship ladder, for [BustleRomance](BustleRomance.md). Opinions are 0 to 100 and compatibility -1 to 1 (see [BustleCompatibility](BustleCompatibility.md)). Each release line sits below its forming line, so a status doesn't flicker. The numbers are experimental defaults.
- [BustleRoomThought](BustleRoomThought.md): One environment thought rule, as data: while an agent is in a room whose `score` is at least `at_least` (a high rule) or at most `at_most` (a low rule), it holds `thought`. [BustleRoomThoughts](BustleRoomThoughts.md) reads it. Bustle ships none; the thresholds are the host's.
- [BustleRoomThoughts](BustleRoomThoughts.md): The environment module: thoughts from the room an agent is in. The host computes rooms and their scores and reports them through the environment port ([BustleEnvironmentPort](BustleEnvironmentPort.md)); this module turns them into held thoughts with [BustleRoomThought](BustleRoomThought.md) rules.
`sync()` holds, for each score of the agent's room, the most extreme high rule it meets (the highest `BustleRoomThought.at_least`) and the most extreme low rule (the lowest `BustleRoomThought.at_most`), so a better score gives a better thought. Every other rule thought is dropped, so leaving the room, or its scores changing, clears or swaps them. A score the room doesn't have is unset and meets no rule. Thoughts go through the mood's `set_held`, so one of each is held at most. Rule thought ids must be the module's own: `sync()` drops any held thought with a rule's id. Nothing is random.
With no environment port, the default one (no rooms) or no mood, there are no environment thoughts and nothing errors.
- [BustleSchedule](BustleSchedule.md): One agent's routine in play: which block of its [BustleScheduleDef](BustleScheduleDef.md) is current, the scorer's `schedule.*` inputs, and attendance. A block is on time when the agent turns up within its lateness tolerance, late when it turns up after that, and missed when it never turns up before the block ends. Time is whole game minutes from the clock port; the season is the clock port's `BustleClockPort.season()` (a block carried over from the night before is read in the current season, and `report()` reads a past day in the season it is given, so pass that day's season across a change of season).
**Wages.** A block with a `BustleScheduleBlock.wage` pays it once, after it ends, if it was attended (on time or late): `settle()` pays every such block through a [BustleTradePort](BustleTradePort.md). Its payer is the block's own, else the `employer` when it was attended, fixed then and saved. A missed block pays nothing; a payment the payer can't make stays owed (kept past the attendance window) and is tried again on every settle until paid.
- [BustleScheduleBlock](BustleScheduleBlock.md): One block of a day's schedule: an activity from one minute of the day to another, at a place. An end at or before the start runs past midnight; the block belongs to the day it starts.
- [BustleScheduleDay](BustleScheduleDay.md): One day's blocks, for a [BustleScheduleDef](BustleScheduleDef.md). Blocks shouldn't overlap; where they do, the one listed first wins.
- [BustleScheduleDef](BustleScheduleDef.md): A routine, as data: a default day, with whole-day overrides by weekday (a rest day, a market day) and by season. A weekday override wins over a season override, which wins over the default. The weekday of a game day is `(day + week_offset) mod week_length`, counting days from minute 0.
- [BustleScheduleRoster](BustleScheduleRoster.md): Every agent's [BustleSchedule](BustleSchedule.md), chosen by job. An agent's job is the first role it holds (in the roles port's sorted order) that [BustleRoleSchedules](BustleRoleSchedules.md) has a routine for; it follows that routine, or its own (`set_own()`) when it has no job. When a role's holder changes, the old and new holders' routines swap at once (`schedule_changed`); attendance and owed wages stay with the agent. A shift's payer is fixed when it is attended (the block's own, else the employer of the job held then), so a later change of job never moves who pays. `settle()` pays every agent's ended shifts through the trade port. After editing `jobs`, call `refresh_all()`.
- [BustleScoreContext](BustleScoreContext.md): What the scorer knows about one agent at one moment: its input values, the options it knows of, its need weights and tag multipliers, and how to check preconditions it doesn't know itself.
- [BustleScoringConfig](BustleScoringConfig.md): The scorer's curves and settings. Anything left unset is neutral (a factor of 1.0, or the identity curve for a need), so nothing here is tuning until a project sets it.
- [BustleSenseTarget](BustleSenseTarget.md): What the project reports about one target to one observer each tick. The project casts the sight ray and fills in `line_of_sight`; the core never touches physics.
- [BustleSenses](BustleSenses.md): What a [BustleBrain](BustleBrain.md) is told on one tick: the game time, the agent's input values (already normalised, see [BustleInputs](BustleInputs.md)) and the options it knows of. Whoever drives the brain (a host, or later modules) fills it in; the brain never reads the scene.
- [BustleSequenceRunner](BustleSequenceRunner.md): Runs one [BustleActionSequence](BustleActionSequence.md) for one agent, a step at a time, with registered [BustleActionHandler](BustleActionHandler.md)s. `wait` and `idle` are registered from the start.
- [BustleSimRingConfig](BustleSimRingConfig.md): How agents are sorted into simulation rings (see [BustleSimRings](BustleSimRings.md)). Every default here is a proposed tunable; projects set their own.
- [BustleSimRings](BustleSimRings.md): Sorts a society's agents into simulation rings by where they are relative to the player, using the society's world and clock ports, and runs each ring. Areas come first, metres second. A ring change touches only the agent's `BustleNpcState.sim_ring` and, with `BustleSimRingConfig.manage_bodies`, its body (which may move its saved position to where the body was or appears); `tick()` and `catch_up()` also let its brain think and set `BustleNpcState.last_update_minute`. Nothing else in its state changes.
- [BustleSkillDef](BustleSkillDef.md): One skill, as data: its id, its top level, how much practice each level costs, how it fades and how much it speeds and improves work. [BustleSkills](BustleSkills.md) reads it. Bustle ships no skills; the host supplies every def. The numbers here are experimental defaults.
- [BustleSkillSet](BustleSkillSet.md): Skill levels. A host or the skills module extends this. The standalone default makes everyone equally skilled.
- [BustleSkills](BustleSkills.md): The skills module: skill levels that grow with practice and fade without it. Install it as the society's skill set with `society.set_port(&"skills", skills)`; a host that doesn't keeps the default, where everyone's level is 0.
Each agent keeps XP per skill, as a float, and its level is worked out from that XP with the skill's [BustleSkillDef](BustleSkillDef.md). XP is added only by `add_xp()` (practice the host or another module reports) and lost only by decay in `advance()`. Nothing is random, so the same practice and time always give the same levels. The skills come from the host's defs; Bustle has none of its own.
A passion ([BustlePassionDef](BustlePassionDef.md)) multiplies the XP practice gives. An agent's passions are the ones the host assigned, or, when it has none, the ones derived from its personality sliders (see `derived_passions()`). `apply()` writes the skill in use onto the agent's [BustleModifierSet](BustleModifierSet.md) as `work.speed` and `work.quality`, and holds a passion's thought in its mood while it does that work.
- [BustleSocialInteractions](BustleSocialInteractions.md): Greetings and interactions between agents, recorded through a social port: give it the society's (`society.ports.social`), so they land wherever that port keeps them. Every interaction goes through one pure function, `outcome()`, which gives the same answer for the same pair, minute, interaction, compatibility and moods; `interact()` then records it: a deed (the verb is the interaction's id) carrying both outcomes, and any thoughts. When the port is the built-in [BustleSocialStore](BustleSocialStore.md), opinion entries whose reason names that deed are added too; any other port weighs the deed itself (a bridge to a social engine can use its magnitude). A greeting is an interaction with cooldowns: one per pair (either way round) and one per initiator, so agents don't greet the same person over and over, or everyone at once.
- [BustleSocialPort](BustleSocialPort.md): How agents feel about each other and what they know of each other's deeds. A host (or a bridge to a social engine) extends this and overrides every method. The standalone default has no opinions or relationship kinds, and keeps a small in-memory list of deeds: the actor and the named witnesses know a deed first-hand, and `share_news()` passes only first-hand deeds, one hop, so nothing spreads further on its own.
- [BustleSocialStore](BustleSocialStore.md): The built-in social store: a [BustleSocialPort](BustleSocialPort.md) that keeps opinions with reasons and relationship kinds, for hosts without a social engine of their own. Deeds work as in the port's default.
**Opinions** are one-way: how `a` regards `b`, from 0 to 100, is `BustleSocialPort.NEUTRAL_OPINION` plus every live opinion entry, clamped. Each entry has a value, a reason (plain data; a `deed` key when a deed caused it) and lasts a number of game days. The store's clock is `set_time()`; entries end at their minute.
**Kinds** are one-way too (`a` counts `b` a friend). Kinds a host sets (`set_kind()`) stay until it clears them. Kinds the `rules` form from repeated deeds come and go with opinion (`kind_changed`); the rules never touch a host's kinds.
- [BustleSociety](BustleSociety.md): The registry of a population: every agent's [BustleNpcState](BustleNpcState.md), independent of any scene, the ports the host plugs in, and saving and loading the whole population.
- [BustleStealAction](BustleStealAction.md): `steal`: takes the agent's target through `BustleCrime.steal()` (which checks every guard again first). Done when the item moved; fails with the reason otherwise (`no_target`, `guards_failed` or `not_moved`).
- [BustleStealthRules](BustleStealthRules.md): The numbers behind [BustleVisibilityModel](BustleVisibilityModel.md) and [BustleNoiseModel](BustleNoiseModel.md). A project supplies its own as a `.tres`; the defaults here are PROPOSED tuning, not final values.
- [BustleThoughtDef](BustleThoughtDef.md): One kind of thought, as data: what it does to mood, for how long, how repeats stack, the emotion it carries and the kind of reason behind it. A thought with a `duration_hours` of 0 lasts while its condition holds (see `BustleMood.set_held()`); a need thought (`need` set) holds while that need's pressure is at least `need_at_least`.
- [BustleTradePort](BustleTradePort.md): Money and buying, in one abstract unit (whole numbers): what the unit is, and any currencies behind it, is the host's business. A host extends this to use its own wallets and shops. The standalone default keeps in-memory balances and a price list. It never creates or loses money: a payment moves an exact positive amount between two different, named agents who can afford it, and anything else fails without changing a balance.
Stock belongs to the host: the default sells any listed item without limit. A host that keeps stock (or lends credit) overrides `can_buy()` and `buy()` together, so an item is only offered when `buy()` would go through, and `can_take()` and `take()` together for an owner using its own stock.
- [BustleTraitDef](BustleTraitDef.md): A trait, as data only: a named bundle of modifiers (rates, weights, tag tastes, mood), slider shifts, needs and goals it adds, and permanent thoughts. No trait has code; a host or a module reads the modifiers by key. A trait may exclude others: an agent can't have both.
- [BustleUtilityScorer](BustleUtilityScorer.md): Scores an agent's goals and picks one. It keeps no state.
- [BustleVisibilityModel](BustleVisibilityModel.md): How visible a target is: the light curve × posture × movement × a clothing factor, times the stealth-skill multiplier, clamped to `min_visibility..max_visibility`. 1.0 is a standing, walking target in full light with neutral clothing and no skill. It keeps no state; the numbers come from [BustleStealthRules](BustleStealthRules.md).
- [BustleWaitAction](BustleWaitAction.md): `wait`: does nothing until `params.minutes` game minutes have passed. A missing, negative or non-finite number of minutes fails the step (`bad_params`).
- [BustleWantDef](BustleWantDef.md): One short-lived want, as data: who it suits (personality and circumstances), when it's fulfilled, how long it lasts and the thought fulfilling it gives. [BustleAspirations](BustleAspirations.md) reads it. Every circumstance, progress input and fact is a name the host fills each update. Bustle ships none.
- [BustleWitnessConfig](BustleWitnessConfig.md): The numbers behind [BustleWitnessJudge](BustleWitnessJudge.md): what someone who knows of a theft does about it. Each outcome's score is `Σ weight × (value − 50) / 100` over its terms, plus any loyalty. Nothing here is a chance.
- [BustleWitnessJudge](BustleWitnessJudge.md): What someone who knows of a theft does about it: exactly one of `OUTCOMES`. The default decision [BustleCrimeWatch](BustleCrimeWatch.md) uses when the host doesn't supply its own (`BustleCrimeWatch.should_report`).
Each eligible outcome gets a score from `config` (the witness's personality, its opinions of the thief and the victim, its fear of the thief and, for a report, the authority's standing with it), and the highest wins. Ties go to the earlier of `OUTCOMES`. Below `BustleWitnessConfig.threshold`, the witness stays silent. Nothing here is a chance, and the same formulas hold for every agent.
Eligibility: a report always; telling the victim when the victim is someone else; confronting when the thief is known and within reach; gossiping when there's someone to tell.
- [BustleWorkPort](BustleWorkPort.md): Jobs. A host extends this to give agents its jobs. The standalone default has none, unless it is given a [BustleScheduleRoster](BustleScheduleRoster.md): then an agent's job is its role that comes with a routine. Posted, one-off work is on an optional [BustleJobBoard](BustleJobBoard.md); standing jobs stay roles.
- [BustleWorkType](BustleWorkType.md): One kind of posted, one-off work, as data: who may take it (a role, a skill level, tags), how much a given agent wants it (personality and circumstances), and what it involves (place, minutes, wage). [BustleJobBoard](BustleJobBoard.md) reads it. Standing jobs are roles and schedules, not work types. Bustle ships none; the host supplies every type. The numbers are experimental defaults.
- [BustleWorldPort](BustleWorldPort.md): Where agents and places are, how areas connect, and how bodies are made. A host extends this and overrides every method. The standalone default is one area, `DEFAULT_AREA`, with everyone in it, places at positions set with `set_place()` (the origin for any other), no travel time, and **no bodies**: it never spawns, frees or moves anything, so it is headless only.
